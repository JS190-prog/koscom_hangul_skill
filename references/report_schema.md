# report.json 스키마 (요약보고)

렌더러가 읽는 입력 형식이다. 에이전트는 사용자가 준 내용을 이 형식으로 정리한 뒤 렌더러를 실행한다.
예시는 `examples/summary_sample.json`에 있다. 원본 Sample(요약보고)의 내용을 그대로 옮긴 것이다.

```powershell
& "<SKILL>\scripts\render.ps1" -Json report.json -Out 결과.hwp
# 직접 실행: java -cp "<SKILL>\lib\hwplib-1.1.9.jar;<SKILL>\scripts\koscom-hwp.jar" Renderer report.json 결과.hwp "<SKILL>\templates"
```

`examples/detail_sample.json`의 그림 경로(`references/examples/img/process.png`)는 스킬 폴더를 현재 폴더로 두고 실행할 때 기준이다.

표준출력 형식:
- 경고는 `WARN …` 줄로 나온다. 이 경고를 보고 문장을 줄이거나 다시 쓴다.
- 성공하면 마지막 줄이 `OK <경로>`이다.
- 실패하면 `ERROR …`를 찍고 종료 코드 1을 돌려준다.

## 최상위

| 키 | 필수 | 설명 |
|---|---|---|
| `type` | | `"summary"`(기본값). 상세보고는 `"detail"`, 기안문은 `"draft"`(아래 각 절). |
| `title` | ✓ | 보고서 제목. 제목 칸을 넘으면 `WARN [제목]`. |
| `approval` | ✓ | `{"담당": "홍길동(1234)", "팀장": "…", "부서장": "…"}`. 이름(내선) 형식. |
| `date` | ✓ | `"2026. 4. 23"` 형식(마침표 뒤 공백). |
| `dept` | ✓ | 작성 부서. 날짜와 합쳐 칸을 넘으면 `WARN [날짜·부서]`. |
| `heading_style` | | `"box"`(□, 기본값) 또는 `"number"`(1. 2. …) |
| `sections` | ✓ | 대제목 묶음 배열 |
| `attachments` | | 첨부·참고 배열(각각 새 쪽에서 시작) |

## 대제목 묶음 `sections[]`

```json
{"heading": "활동 개요", "items": [ … ]}
```

## 항목 `items[]`

| `type` | 모양 | 키 |
|---|---|---|
| `o` (기본값) | `  ㅇ (라벨) 본문` | `label`(선택, 굵게), `text`, `children` |
| `num` | `  ① 본문`(전체 굵게) | `num`(생략하면 ①②③ 자동), `text`, `children` |
| `dash` | `    - (라벨) 본문` | `label`, `text`, `children` |
| `dot` | `      · 본문` | `text`, `children` |
| `note` | `      * 각주`(함초롬돋움 12) | `text` |
| `ref` | `     ※ 참고`(함초롬돋움 12) | `text` |
| `table` | 삽입 표 | 아래 "표" 절 참고 |
| `box` | 노란 강조 박스 | `title`, `items`(각 항목은 `o`/`dash`/`ref`, `label` 가능) |

- 하위 단계는 `children`에 넣는다(ㅇ → - → ·). 각주(`note`)는 `*`가 붙은 항목의 `children`에 넣는다.
- 본문 안의 `**굵게**`는 굵은 글자로 바뀐다(표 칸, 박스 안에서도 됨).
- 본문에서 글자 바로 뒤에 붙은 `*`(예: `10명*`)는 위첨자 각주 표시가 된다.
- `text` 앞에 `ㅇ`, `-`, `·` 같은 머리 기호를 넣어도 렌더러가 지운다(원형이 붙임).

## 표 `{"type": "table", …}`

```json
{"type": "table", "style": 2, "header_rows": 1,
 "widths": [1, 2, 3, 2], "align": ["center", "center", "left", "center"],
 "rows": [
   ["구분", "과제명", "주요 성과", "실행 부서"],
   ["**1기**", "**사내 기술력\n강화**", "통합개발환경 조성", "개발도구도입TF부"],
   ["**2기**", "**디지털\n업무환경 개선**", "외부망 텍스트 복사 기능 추가", "정보보호부"],
   ["^", "^", "야간 장애발생 시\n업무망 접속 허용", "정보보호부"],
   ["^", "**Green\nKoscom**", "층 별 텀블러 세척기 도입", "경영지원부"]
 ]}
```

| 키 | 기본값 | 설명 |
|---|---|---|
| `style` | 1 | 1 = 격자(모든 선, 회색 머리행) / 2 = 좌우 개방(머리행 아래 이중선, 맨 아래 굵은 선) |
| `rows` | (필수) | 행 배열. 열 개수는 자유롭게 정할 수 있고, 짧은 행은 빈칸으로 채운다. 머리행 + 본문 1행 이상 필요. |
| `header_rows` | 1 | 머리행 수. 2단 머리행이면 2. |
| `widths` | 자동 | 열 너비 비율. 생략하면 각 열에 가장 긴 줄이 한 줄로 들어가는 폭을 주고, 표 폭을 넘으면 넓은 열부터 깎는다. 좁은 열은 유지되고, 남는 폭은 비율대로 나눈다. |
| `align` | 모두 가운데 | 열별 본문 정렬 `"center"` / `"left"`. 왼쪽 정렬 칸에는 좌우 1.8mm 안쪽 여백이 붙는다. |

칸 값 규칙:
- `"^"`: 바로 위 칸과 세로 병합
- `"<"`: 바로 왼쪽 칸과 가로 병합
- 병합 범위는 직사각형이어야 한다. 아니면 `ERROR 병합 범위가 직사각형이 아님`.
- `"\n"`: 칸 안 줄바꿈. `**굵게**`가 줄을 넘어가도 각 줄에 굵게가 이어진다.
- 숫자도 그대로 쓸 수 있다(`120` → "120").

렌더러가 자동으로 처리하는 것:
- 행 높이를 칸 글자 줄 수에 맞춘다. 병합 칸이 더 높이를 필요로 하면 그 칸의 마지막 행을 늘린다.
- 테두리를 칸의 위치(머리행/첫 본문 행/중간/마지막 행 × 첫/중간/끝 열)에 맞게 고른다.
- 쪽이 넘어가면 행 단위로 나누고 머리행을 반복한다.

## 첨부·참고 `attachments[]`

```json
{"kind": "첨부", "title": "제2기 주니어보드 운영결과", "sections": [ … ]}
```

- `kind: "첨부"`: 첨부 라벨 박스 아래에 본문 블록으로 쓴다.
- `kind: "참고"`: 참고 라벨 박스 아래 **점선 박스 안에** 본문 블록을 넣는다.

## 상세보고 `{"type": "detail", …}`

예시는 `examples/detail_sample.json`에 있다(원본 Sample(상세보고) 내용, 결재라인은 가명).

| 키 | 필수 | 설명 |
|---|---|---|
| `title` | ✓ | 표지 제목(HY헤드라인M 32). 2줄이 넘으면 `WARN [표지 제목]`. 제목이 여러 줄이면 표지 빈 줄을 자동으로 줄여 한 쪽에 맞춘다. |
| `date` | ✓ | `"2026.3"` 형식 |
| `hq`, `dept` | ✓ | 본부, 부서(표지) |
| `approval` | ✓ | `{"담당": …, "팀장": …, "부장": …}` |
| `cover` | | `"full"`(로고 표지 + 별도 목차 쪽, 기본값) / `"compact"`(제목·장 목차·날짜·부서를 한 쪽에) |
| `toc` | | `false`면 정식 표지에서 목차 쪽을 뺀다 |
| `heading_style` | | 대제목 기본 모양 `"number"`(1. 2., 기본값) / `"box"`(□) |
| `chapters` | ✓ | 장 배열 |
| `attachments` | | 요약보고와 같다. 목차에 `<별첨>`으로 들어간다. |

```json
"chapters": [
  {"title": "작성 목적",                       // → "I. 작성 목적" 장 제목 박스(새 쪽)
   "sections": [ {"style": "box", "heading": "…", "items": […]} ],   // 절 없이 바로 대제목
   "parts": [
     {"title": "중기 경영계획 수립",           // → [1] 중기 경영계획 수립 절 박스
      "sections": [
        {"heading": "개요", "items": […]},
        {"heading": "세부 내용", "page_break": true, "items": […]}
      ]}
   ]}
]
```

- 장 번호(I, II, …)와 절 번호(1, 2, …)는 자동으로 붙는다. 대제목 번호(1. 2.)는 절마다 새로 센다.
- 묶음(`sections[]`)별로 `"style"`로 대제목 모양을 바꿀 수 있고, `"page_break": true`면 그 대제목에서 새 쪽을 시작한다.
- 쪽번호는 표지·목차에서 감추고, 첫 장에서 1쪽으로 새로 시작한다.
- **목차 쪽번호는 추정값**이다. 문단 높이를 합산해 계산하므로 항상 `WARN`으로 알린다. 예시 문서에서는 실제와 모두 일치했다.

### 그림 `{"type": "figure", …}` (상세보고)

```json
{"type": "figure", "path": "references/examples/img/process.png", "width": 150, "caption": "<그림 1> 경영계획 수립 프로세스"}
```

- `path`: png/jpg/bmp/gif. 상대 경로는 렌더러 실행 폴더 기준이다.
- `width`: 그림 너비(mm). 생략하면 원본 크기(96dpi 기준)로 넣되, 본문 폭을 넘지 않게 맞춘다.
- `caption`: 그림 아래 가운데에 함초롬돋움 12로 붙는다.
- 그림은 글자처럼 취급되어 가운데 정렬 문단에 들어간다.

## 기안문 `{"type": "draft", …}`

예시는 `examples/draft_sample.json`에 있다. 머리(로고·수신자·제목 칸)와 꼬리(`첨부 //. 끝.` 줄, 결재·협조·시행·주소 칸)는 전자결재 시스템이 만드는 영역이라 기본은 **양식 그대로** 두고, 그 사이 본문만 만든다. 수신자·제목·첨부 목록은 `recipient`·`title`·`attachments`를 주면 채운다(인쇄용 완성본). 결재라인·시행 정보는 받지 않는다.

| 키 | 필수 | 설명 |
|---|---|---|
| `basis` | | 관련 근거 배열. 1건이면 `1. 관련 근거 : …` 한 줄, 2건 이상이면 `가.` `나.` …로 나눈다. 비우면 관련 근거 줄 없이 요청 문장이 1.이 된다. 형식은 `"부서연도-번호(시행일 : 문서명)"` |
| `purpose` | ✓* | 추진하는 일(목적어). `2. 위 근거에 의거, 아래와 같이 {purpose}을/를 추진하고자 하오니 결재하여 주시기 바랍니다.`가 된다(조사는 받침으로 고름) |
| `request` | | 요청 문장 전체를 직접 쓸 때(`purpose` 대신). 번호 `2.`는 렌더러가 붙인다 |
| `label_style` | | `"colon"`(기본, `ㅇ 배경 : 내용`) / `"paren"`(`ㅇ (배경) 내용`, 라벨 굵게) |
| `sections` | ✓ | `- 아 래 -` 아래 번호 항목. `{"heading": "추진 개요", "text": "(선택) 제목 줄에 붙일 내용", "items": […]}` |
| `recipient` | | 머리 수신자 칸(예: `"경영지원부장"`, `"내부결재"`). 비우면 양식 안내 문구 그대로 |
| `title` | | 머리 제목 칸(예: `"○○ 추진 및 계약 체결 의뢰"`). 비우면 양식 안내 문구 그대로 |
| `attachments` | | 첨부 목록(문자열 배열, 각각 `"문서명 1부"`). 꼬리 첫 줄을 `첨부 1. …` / `     2. …` / 마지막 `… 1부. 끝.`로 바꾼다(1건이면 `첨부 … 1부. 끝.`). 비우면 꼬리의 안내 줄을 빼고 본문 마지막 줄 끝에 `  끝.`을 붙인다(마지막이 표면 다음 줄에 `끝.`) |

- 번호 항목 제목은 `1. 추진 개요`(굵게)이다. `text`를 주면 `4. 소요 예산 : 1,000,000원(부가세 별도)`처럼 한 줄에 붙는다.
- 항목 `type`은 `o` · `dash` · `dot` · `note`(*, 11pt) · `ref`(※, 11pt) · `table`이다(`num`·`box`·`figure`는 기안문에 없음). `label`을 주면 위 `label_style`대로 붙는다.
- 표에 `"unit": "(단위 : 원, 부가세 별도)"`를 주면 표 바로 위 오른쪽에 붙는다. 표 서식은 양식의 예산 현황 표(머리행 회색, 격자)이고 `"style": 2`는 좌우 열림 표다. 마지막 행 첫 칸이 `합계`(또는 `총계`)면 양식처럼 그 행을 옅은 회색 바탕으로, `합계`를 굵게 쓴다. 앞 두 칸 병합은 `["합계", "<", "", "금액"]`처럼 준다.
- 빈 줄(맑은 고딕 12pt)은 양식대로 번호 항목 앞, 항목 제목과 첫 내용 사이, ㅇ 항목 사이에 자동으로 들어간다. 표 앞뒤에는 넣지 않는다.
- 글자는 검정이다(양식의 파랑·초록 글자는 안내용 색). 둘째 줄은 머리 기호 다음 글자에 맞춘다(견본에서 잰 내어쓰기).
- 결재 · 협조 · 시행 칸(꼬리 표)은 작성사례처럼 쪽 아래에 붙인다(표 위치 : 쪽 기준 아래, 자리 차지). 양식에 있던 표 앞 빈 줄 27개는 한 줄만 남긴다 — 빈 줄로 밀어 내리면 본문이 길 때 결재 칸만 다음 쪽으로 넘어갔다.

## 렌더러가 자동으로 하는 일

| 항목 | 규칙 |
|---|---|
| 간격 | 제목 박스·첨부 박스 다음 10pt, 대제목 묶음 사이 12pt, ㅇ·①·박스 앞 8pt, - 앞 6pt, ·/*/※ 앞 4pt, ※ 바로 뒤 표는 간격 없음 |
| 자간 | 본문 15pt 항목에서 마지막 줄 1~6글자 걸침이나 단어 중간 끊김이 생기면 자간을 0~-12% 중 가장 나은 값으로 줄인다(머리 기호 부분은 제외) |
| 표 행 높이 | 칸 글자 줄 수만큼 행을 높인다 |
| 제목 붙임 | 대제목·①·장·절 제목은 "다음 문단과 함께" 속성으로 쪽 끝에 혼자 남지 않는다 |
| 내어쓰기 | 대제목과 강조 박스 안 ㅇ·- 항목도 둘째 줄을 기호 다음 글자에 맞춘다 |
| 경고 | 3줄 초과 항목, 제목·결재라인·날짜·부서 칸 넘침, 표지 제목 2줄 초과, 목차 쪽번호 추정 안내 |

줄 수 계산은 `Layout`의 근사 모델이다. 한컴 뷰어 화면에서 관찰한 줄바꿈 11건과 자간 측정값으로 보정했고, 함초롬바탕 15pt 기준이다. 기안문(맑은 고딕 12pt)은 글자가 약 2% 넓어 본문 폭을 그만큼 줄여 계산한다(한글 화면의 줄 끝 6곳으로 맞춤, `DraftRenderer.MALGUN`). 경계에 걸린 줄은 한 어절쯤 어긋날 수 있으므로, 최종 결과는 뷰어에서 확인한다.
